## 持续执行提示词

用户于本轮追加授权：仅为补齐纯核心配置验证／应用接口，发布 Runtime `v2.0.0-dev.24`，
随后 CLI 和 Client2 使用该新基线并发布 DEV，最终验证公开产物。
沿用 Runtime23 锁定的 Core SDK；本轮不修改 Core 或数据库格式。Runtime 改动只限
核心配置候选验证、运行态应用及真实状态回执。超出该范围的基线修改仍交用户决定。

按组件职责文档执行：Core 提供数据库、加密、模型执行及记忆算法；Runtime 提供核心
登录、同步、数据库生命周期、recall、remember 及 RPC/MCP；CLI 与 Client2 负责下载、
安装、组件选择、私钥保管、系统钥匙串、安全传钥、自启及 Runtime 进程维护。
agent-config 的读取、校验与持久化属于宿主；配置回读不能冒充 Runtime 已应用。
运行时参数通过已有核心接口或身份已核验的重启流程应用，不能继续委托 Runtime 写宿主文件。

先核实现有代理及工作树，继续已有任务，避免重复开发。每项任务使用独立分支和
`.worktrees/<任务名>/<仓库名>`；四个主仓保持只读。独立阻塞并行处理，CLI 优先发布。
保留旧 rsrs 命令、参数、退出码、JSON、插件和 MCP 入口。CLI 与 Client2 独立版本，
按协议配合；只要求新宿主适配 Runtime24，不扩展旧宿主和新 Runtime 的组合矩阵。

历史升级重点验证数据库：旧正式版及改变数据库格式的 DEV 检查点，升级后用原密钥
解密旧数据，检查完整性、待同步数据、remember、recall 和同步。格式未变的 DEV
不增加组合。不要求保留历史会话、凭据存放位置或派生索引。

使用隔离合成账号、钥匙串和数据库。PR 阶段运行受影响的现有检查及必要定向复验，
不重复完整原生矩阵。最后针对发布候选并行完成完整验收，发布已验证的同一批字节，
核对公开来源、版本和摘要。不得绕过发布保护，不得用 mock、吞错、假成功、静默降级
或未经授权的 fallback 掩盖失败。Rust 不新增 unwrap/expect。

最终验收覆盖：公开安装升级；CLI/Client2 拉起、停止和自启 Runtime；无宿主输入重启
保持锁库，宿主取钥后自动解锁；登录及密钥续接的事务一致性；同步、remember、recall；
上述历史数据库升级。源码 CI 通过不能代替实际产物验收。

必要修复合并、两个新 DEV 公开可获取、职责文档与实现一致、全部必要验收有实际证据后，
才将 goal 标记完成。持续报告实际阻塞和未验证项；无法可靠估时就明确说明。
